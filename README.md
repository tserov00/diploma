# Demo Broker

Учебное приложение для симуляции торговли акциями Московской биржи. Все сделки виртуальные: сервисы приложения не отправляют биржевые поручения.

## Возможности

- регистрация, JWT-аутентификация и отдельные PostgreSQL-базы микросервисов;
- рыночные и лимитные заявки на покупку и продажу;
- резервирование денег для покупок и бумаг для продаж;
- исполнение по лучшей доступной цене bid/ask с учётом показанного объёма верхнего уровня;
- история исполнений с ценой, временем рыночного снимка и источником данных;
- карточка инструмента с графиком исторических свечей на TradingView Lightweight Charts.

Лимитная покупка исполняется, если ask не выше лимита; лимитная продажа — если bid не ниже лимита. Если текущая котировка уже подходит, заявка проверяется при создании. Оставшиеся открытые заявки проверяются общим обработчиком по каждому инструменту с активными заявками. Рыночная заявка исполняется по доступному объёму лучшего уровня; неисполненный остаток отменяется, резерв освобождается.

## Рыночные данные

По умолчанию `market-service` использует публичный HTTP API ALOR для `MOEX`. Анонимные котировки и история доступны без пользовательского токена, но котировки задержаны и не являются live. В интерфейсе показываются источник и время снимка. Котировка содержит лучшие bid/ask, а не полный стакан. В анонимном режиме сделки симулируются по этим ценам и видимому объёму.

Для запуска демонстрации без внешнего поставщика задайте `MARKET_DATA_PROVIDER=DEMO`. Этот режим генерирует синтетические котировки и свечи, помечая их как `DEMO`.

```env
MARKET_DATA_PROVIDER=DEMO
```

## Архитектура

- `gateway-service` — интерфейс, JWT и единая точка входа;
- `auth-service` — регистрация и аутентификация;
- `market-service` — каталог MOEX и адаптеры ALOR/DEMO;
- `order-service` — заявки, фоновая проверка, виртуальные исполнения и портфели;
- `savings-service` — счета, резервы и денежные проводки.

Сервисы взаимодействуют по REST. Kafka и прежнее сопоставление заявок пользователей между собой удалены: контрагентом симуляции выступает внешний рыночный снимок, а не искусственные заявки в базе.

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Откройте `http://localhost:7070`. ALOR не требует ключа для базовых HTTP-котировок. При проблемах с доступом к сети используйте `MARKET_DATA_PROVIDER=DEMO`.

Миграции Flyway запускаются самими сервисами. При переходе со старой схемы торговые заявки и транзакции прежней двусторонней модели, а также портфельные позиции старого каталога будут удалены и созданы заново; денежные балансы сохраняются, старые резервы средств снимаются. Не удаляйте PostgreSQL volumes, если нужно сохранить учётные записи и балансы.

Для графика используется локально сохранённая Lightweight Charts 4.2.2; открыть страницу графика можно без загрузки библиотеки из интернета. Уведомление об авторстве TradingView и ссылка показаны под графиком.

## Основные настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MARKET_DATA_PROVIDER` | `ALOR` | `ALOR` или `DEMO` |
| `ALOR_BASE_URL` | `https://api.alor.ru` | Базовый URL ALOR HTTP API |
| `MARKET_DATA_REFRESH_INTERVAL_MS` | `60000` | Интервал обновления каталога котировок |
| `ORDER_PROCESSING_INTERVAL_MS` | `10000` | Интервал проверки активных лимитных заявок |
| `MARKET_QUOTE_MAX_AGE_SECONDS` | `2700` | Максимальный возраст снимка для симуляции исполнения |
